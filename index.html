策略理论与执行规则

1. 为什么 GitHub Actions 负责指数历史，前端负责溢价？

指数5/10/20日累计涨跌、大跌簇、滚动预算需要连续历史数据，最适合由 GitHub Actions 每天早上自动生成 data/latest.json。国内ETF实时溢价更适合前端抓取，因为它需要盘中刷新，也便于在接口失败时手动输入。

2. 纳指100：固定5000基准 + 三项压力机制

基础四档：≥+1.5% 买2500；-1%~+1.5% 买5000；-2%~-1% 买7000；≤-2% 买8000场外 + 4000场内候选。40年数据没有推翻5000基准，真正需要控制的是连续阴跌和连续暴跌。

阴跌补丁：近5日累计≤-3%，且5日内无单日≤-2%，则把原本5000/7000提升到场外8000；不碰场内，不承担溢价风险。

大跌簇：近5日内第3次出现≤-2%，暂停场内4000候选，只保留场外8000。

滚动预算：5日4万 / 10日7万 / 20日14万；触发时优先削减场内候选。

3. 标普500：轻量版压力机制

标普波动小于纳指，场外2000固定。跌-1%~-2%时场内候选3000；跌-2%~-3%时场内候选8000；跌≤-3%时场内候选15000。

阴跌补丁：近5日累计≤-3%，且无单日≤-2%，总候选提升至5000，即场外2000+场内3000。

大跌簇：近5日内第3次≤-2%，总候选降至5000。

滚动预算：5日3万 / 10日5万 / 20日9万，主要限制场内大额候选。

4. 折后便宜度如何决定场内是否执行？

公式：折后便宜度 = 1 - (1 + 指数涨跌幅) × (1 + ETF溢价)。例如指数跌2%，ETF溢价1%，折后便宜度约 +1.02%，说明跌幅足以覆盖溢价；如果指数跌1%，ETF溢价2%，折后便宜度约 -0.98%，说明并不便宜。

纳指场内4000候选要求：纳指≤-2%、最低溢价≤1.5%、折后便宜度>0，且未被大跌簇/预算禁止。标普场内候选要求：最低溢价≤3%、折后便宜度>0。
